## Per-cluster findings

### GSD (72)

- **Suggestive but not conclusive:** the local body includes a `<codex_skill_adapter>` block; the phrase also appears in `rokicool/gsd-opencode/bin/install.js`. However, local `SKILL.md` files differ from that repository at `main`.
- **Original upstream:** `gsd-build/get-shit-done` (MIT) is **archived**; latest release `v1.42.3`. Its package version is canary `1.50.0`.
- **Version:** unknown. The only local `1.4.0` string is an `--next` RC example in `gsd-update/SKILL.md`, not a version declaration. Do **not** call these stale based on version alone.
- **Assessment:** 72 skills from a GSD-style workflow, likely a fork/adaptation. Large instruction surface; exact origin unproven.
- **Decision:** do not delete. Either upgrade from a verified commit or quarantine the whole cluster after review. No local modifications can be proven without an upstream diff.
- **Still used?** Unknown; no usage logs were read.

### Penpot + migrated commands (18)

- **Evidence:** all files written within one second on 2026-09-19; `version: 0.2.0`; `source-command-*` descriptions say "Migrated source command".
- **Upstream:** no matching public skill repository found. The official Penpot MCP (`penpot/penpot-mcp`, MPL-2.0) is an MCP server, not this skill bundle. A third-party repo with a matching description exists (`ar27111994/penpot-mcp`, MIT) but its tree does not contain these skill files.
- **Assessment:** generated locally by a Penpot setup/migration. Treat as locally authored, unknown license.
- **Decision:** keep; document as local. If publishing, review for copied official text.

### Maestri (6)

- Generated by the Maestri/Maestro desktop app (`~/.maestri/manifest.json`, appVersion `0.23.1`). App-specific actions (canvas, portal, routines).
- **Assessment:** companion-app skills, not portable. No upstream license found.
- **Decision:** keep while the app is installed; do not publish without permission.

### Moli (3)

- Upstream verified: `lexmount/moli` (Apache-2.0, active). Skills reference the official installer.
- **Local state:** no `moli` binary, no `~/.moli` or `~/.config/moli`; skills installed 2026-10-12 but the tool is absent.
- **Assessment:** stale/orphaned candidates.
- **Decision:** reinstall Moli or remove the skills later (approval required).

### GitNexus (12)

## Recommendations (no destructive action)

1. Adopt the canonical store (see `skill-dedup-plan.md`) only for locked/verified skills.
2. For each cluster, choose one of: **document**, **reinstall from verified commit**, **quarantine**.
3. Add a `license` field upstream before publishing any skill content.
4. Keep locally authored skills (OMP managed, Maestri, Penpot) out of the public repository.
5. Re-run the triage after a month; the environment changes frequently.
